# SaaS Revenue & Retention Observatory

**Independent portfolio project | synthetic data | reproducible analysis.** Designed around product analytics decisions; not affiliated with Microsoft and not evidence of real commercial impact.

## Start here

Read [the executive brief](reports/executive_brief.md), open [the interactive report](reports/dashboard.html) in a browser, and inspect [tests](tests/test_contracts.py). Charts in reports/ can be used in your GitHub README or portfolio with the synthetic-data label intact.

## Reproduce (Windows / Python 3.12)

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python src/pipeline.py
python -m unittest discover -s tests -v
python src/ai_reporting.py
python src/publish_report.py
python src/publish_report.py
```

The pipeline deterministically regenerates raw inputs and analysis using seed 20261011. It overwrites data/ and analytical reports; do not replace those synthetic input files with real data without adapting the ingestion step. The browser report is regenerated by publish_report.py. Excel is a checked snapshot; refresh instructions are in excel/README.md. Power BI refresh must be configured separately. CI validates the Python/SQLite pipeline on every push; it does not claim Power BI or Excel execution.

For the versions tested in this delivery, use `pip install -r requirements-tested.txt`. After setup, `python run_project.py` refreshes reports and runs validation.

## What to demonstrate in an interview

Explain MRR versus revenue, reconcile the movement bridge, show why reactivation is excluded from NRR, and distinguish unobserved cohort cells from zero retention.

Run a failing test scenario before showing the happy path. Explain that regional RLS must also restrict summary tables. Inspect query plans and disclose that server dialects are supplied but not executed against a server here.

## Scope and honest claims

Python, pandas, NumPy, Matplotlib, Seaborn, SciPy and SQLite results were run locally. SQL Server/MySQL scripts, DAX and M are implementation assets requiring target-engine testing. A completed [Power BI Desktop report](powerbi/SaaS%20Revenue%20Analytics.pbix) and editable project files are included. See [report validation and refresh instructions](powerbi/REPORT-READY.md). No published Power BI Service report is claimed. AI prompts are prepared; no live model integration or AI-produced findings are claimed. Real native Excel PivotTables require the supplied setup step if the packaged workbook does not contain one.

## Learning checkpoints

1. Reproduce outputs and explain every KPI denominator.
2. Change a generator assumption and predict which output should move.
3. Execute the SQL Server or MySQL scripts in your own database.
4. Build the Power BI report, validate RLS as a Viewer, and capture your own screenshots.
5. Only then present the work as a project you can explain and maintain.
